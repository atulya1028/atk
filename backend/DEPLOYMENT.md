# Hosted deployment guide

The repository includes a Render Blueprint at `../render.yaml`. It provisions the API in Singapore, generates the JWT secret, and prompts for Prisma Postgres pooled/direct connection URLs, SMTP email credentials, and allowed web origins. The API health check is `/health/ready`.

## Before creating cloud resources

1. Put this project in a GitHub repository and connect that repository to Render.
2. Review the API service plan in Render and the database plan in Prisma Console before creating resources. Hosting may incur charges; no cloud resource has been created from this local workspace.
3. Set up a transactional email provider and verify the sender domain/address. Use the SMTP host, port, username, and password from that provider. Email OTP codes are generated by the API, stored only as keyed hashes, expire after 10 minutes, and are never logged or returned.
4. In Prisma Console, create a Postgres database. Choose a region close to your API. Open **Connect to your database**, generate connection strings, and copy the **pooled** and **direct** URLs. In Render's Blueprint prompts, use the pooled URL for `DATABASE_URL`, the direct URL for `DIRECT_URL`, and set `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `OTP_FROM_EMAIL`, and `APP_ORIGINS`. Keep these credentials private. Prisma documents the pooled URL for runtime queries and the direct URL for migrations [here](https://www.prisma.io/docs/postgres/database/connecting-to-your-database).
5. Deploy the Blueprint. The container runs database migrations before the API starts. Confirm Render reports the `/health/ready` health check as healthy and review its logs.
6. From the repository root, build the mobile app with the deployed HTTPS API URL:

   ```sh
   cd app
   flutter build apk --release --dart-define=ATK_API_URL=https://YOUR-API.onrender.com
   ```

   Android publishing also requires your own release signing key. Copy `android/key.properties.example` to `android/key.properties`, create the keystore at the configured `storeFile` path, and fill in its passwords and alias. Release builds are no longer signed with the development debug key. Do not commit the properties file or keystore.

7. Send a real OTP to an email inbox you control, verify it, save a profile, and confirm that a new login retains the profile. Set an uptime monitor to request `/health/ready` and alert on failures. Enable the database backup/retention option appropriate for your chosen Render plan and run a restore drill before launch.

The Blueprint leaves the API compute plan to Render defaults so you can review current pricing in the dashboard before creation. Prisma Postgres billing and connection limits are managed in Prisma Console.
